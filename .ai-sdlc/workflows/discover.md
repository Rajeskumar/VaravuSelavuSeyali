# Discover — product manager

Read the relevant current product specification and feature status. Brainstorm in natural language:
who has the problem, what outcome matters, what already exists, alternatives (including no change),
boundaries, permission/empty/error/offline cases, and how success will be measured.

Create a work item only when the discussion needs a durable outcome. Use the requirement template;
record stable AC IDs in work-item.json, user decisions and unresolved questions. Do not invent user
research or silently turn suggestions into requirements. Resolve material ambiguity before Plan;
state assumptions that can safely be carried forward. Stop at requirements when asked only to explore.

Exit: the user and product persona have an agreed problem, scope, outcomes and exclusions. Run the
Discover gate for artifact completeness, then assess requirement quality against the original request.
