# Implementation plan — TS-GA4-002

Status: planned. Semantic risk high (personal data, external destination, consent); priority P1; size L. Requirements: requirements.md; AC text: work-item.json; tests: test-plan.md.

## Architecture and contracts
Direction stays app → features → core (`src/core/boundary.test.ts`). Prior art to port, not import: `varavu_selavu_ui/src/analytics/` (`events.ts` closed schemas + `validateEvent`, `client.ts` consent/generation/operation tokens, `operations.ts` `observe/confirmed/expenseCreation/safeFailure`).

- **Shared contract:** `docs/analytics/catalog.v1.json` — event names, features, property enums, platforms (`web|ios|android`), per-event platform support. Web test (`events.test.ts`) and mobile test both assert their `events` table equals the catalog; `docs/analytics/event-catalog.md` stays the human description and gains a mobile section (no duplicate spec).
- **`core/analytics/` (product-agnostic):** `client.ts` (consent per category, generation counter, operation tokens, 1,000 / 30 min bound, no-throw wrapper), `validate.ts`, `providers/{firebase,noop,recording}.ts`, `screens.ts` (route name → registered screen id; unknown → `unknown`; params never read), `crash.ts` (sanitizers, non-fatal reporter, breadcrumbs = allowlisted event names only), `consent.ts` (two SecureStore keys, per account-agnostic device choice, cleared by nothing on sign-out except analytics identity reset). App-specific catalog and screen registry are supplied via `AppConfig.analytics`, not imported by core.
- **Producers (features):** wrap existing API functions with the confirmed-write pattern: success only after the server acknowledgement, one terminal event per operation token, `outcome_unknown` for lost replies, never replay a write. Screens call helpers, never Firebase. Chat-created expenses use the entry method the catalog reserves; `ai_query_*` mirror web.
- **Screen tracking:** `NavigationContainer` `onReady` + `onStateChange` in `RootNavigator`; emit only when the active leaf route name changes; param-bearing routes (MerchantDetail, ItemDetail, GroupDetail, JoinGroup) report the route name only. Firebase automatic `screen_view` disabled (`google_analytics_automatic_screen_reporting_enabled=false` on both platforms).
- **Environment:** `EXPO_PUBLIC_ANALYTICS_ENV` ∈ `production|qa`, anything else (unset, `e2e`, tests, web preview) → no-op provider. Firebase config files are not committed; `app.config.js` (new, wraps `app.json`) points `googleServicesFile` at paths from `GOOGLE_SERVICES_PLIST` / `GOOGLE_SERVICES_JSON` only when the env is set. Collection defaults off in `firebase.json` (`analytics_collection_enabled=false`, `crashlytics_auto_collection_enabled=false`) and is switched on only after the matching consent. The E2E variant forces no-op.
- **Advertising/privacy:** config plugin disables IDFA (no `AdSupport`), `google_analytics_adid_collection_enabled=false`, `google_analytics_default_allow_ad_personalization_signals=false`, removes `AD_ID` from the Android manifest; no ATT prompt. Review `PrivacyInfo.xcprivacy` merged from Firebase pods and document residual SDK metadata (app instance id, device/OS, geography from IP).
- **Crashlytics:** native fatals; JS exceptions through the error boundary and a global handler as sanitized non-fatals (`error.name` + fixed code only, no message, stack text redacted of URLs); custom keys limited to `app_version`, `build`, `env`, `platform`. dSYM upload via the Crashlytics build phase; Android mapping via the Crashlytics Gradle plugin (config-plugin applied). Test crash control exists only when env is `qa`.
- **Identity:** no User-ID. Reset = `resetAnalyticsData()` and generation bump on explicit sign-out, 401 forced sign-out and account change (follow the access token, not the cleanup registry, because forced sign-out skips cleanups).
- **Template-ready (owner, 2026-11-25):** the reusable shell must lift into `cerebroos-mobile-app-template` (`docs/mobile/CORE_BOUNDARY.md`). So: (1) `core/analytics` has no TrackSpense names — the event list and screen registry come from `AppConfig.analytics`; (2) core ships only cross-app events (`screen_view`, `permission_result`, consent, auth, crash) plus the `platform` field, while expense/receipt/group/AI events and their producers live in `features/`/`app/`; (3) Firebase config plugins are generic files with no TrackSpense identifiers (app-specific values from env/config); (4) runbook and privacy wording separate a generic section from TrackSpense-specific text. `boundary.test.ts` keeps enforcing it. Porting into the template repo is a **separate follow-up work item (T11), started only after this item is working and validated**; it is not part of TS-GA4-002 and touches no other repository here.
- **Alternatives rejected:** Firebase JS SDK (no RN analytics/Crashlytics); Measurement Protocol from backend (needs new infrastructure and PII risk); one combined consent (owner chose separate).

## Risks and safeguards
Trust boundary: app state → typed allowlist → validator → consent/environment gate → Firebase SDK → Google. Whole-event rejection on unknown event/key/value; diagnostics log reason codes only, never values. Failure cases: analytics throws or is unavailable (product unchanged); consent withdrawn while an operation is in flight (send-time re-check); account switch with stale callbacks (generation check); lost write replies (`outcome_unknown`, no retry); deep-link token and group/merchant ids never reach analytics or crash keys; JS stack traces are minified (Hermes) — residual, documented. Native build risk gated by Task 0. Financial values, descriptions, receipt contents, tokens and raw API responses never cross the boundary. Migration: none. Performance: no added network on the hot path; SDK startup measured in Task 0.

## Rollout and recovery
Default build is the no-op provider; analytics reaches users only in a build that sets `EXPO_PUBLIC_ANALYTICS_ENV=production` with config files, after owner-run Firebase/GA4 setup (runbook) and separate release authorization. Recovery: rebuild without the variable (no-op), or turn off collection in the Firebase project; Crashlytics collection is also remotely gated by consent. No backend or database change.
